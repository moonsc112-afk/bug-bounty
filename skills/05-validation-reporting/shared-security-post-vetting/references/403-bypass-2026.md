# Catatan kerja: 403 bypass yang masih relevan (2026)

Tiga kelas yang masih dipakai: header override, method tampering, parser discrepancy.
Prinsip: 403 adalah keputusan satu layer. Bypass terjadi saat front-end dan backend
tidak sepakat tentang arti request yang sama.

Tanda layer depan: response polos, beda Server header, body jauh lebih pendek.

## A. Header override

```
X-Original-URL: /admin
X-Rewrite-URL: /admin
X-Forwarded-For: 127.0.0.1
X-Real-IP: 127.0.0.1
X-Custom-IP-Authorization: 127.0.0.1
```

Uji PortSwigger: `GET /admin` kena 403. Ubah request line jadi `GET /`, tambah
`X-Original-URL: /invalid`. Kalau dapat "not found", backend memakai header itu.
Ganti ke `/admin` → 200. Aksi: `GET /?username=carlos` + `X-Original-URL: /admin/delete`.
Efek samping: log forging, cache poisoning. PortSwigger: CWE-436 Interpretation Conflict.

## B. Method tampering

```
GET /admin → POST /admin, HEAD /admin, OPTIONS /admin, PUT /admin
POST /admin + X-HTTP-Method-Override: DELETE|PATCH
POST /admin + _method=DELETE        (Express method-override)
FOO /admin                          (method buatan)
```

F5 K000163578 (Oct 2026): BIG-IP ASM blok DELETE/PATCH langsung tapi bisa lolos
lewat POST + X-HTTP-Method-Override. Express method-override harus dipasang
sebelum middleware auth. OWASP: PUT/DELETE di REST API bukan temuan; yang jadi
temuan adalah beda perlakuan auth atau validasi antar method (misal HEAD /admin
200 + Set-Cookie admin sementara GET /admin 302 login). TRACE/TRACK sudah mati.

## C. Parser discrepancy

```
/admin/..
/./admin
//admin//
/admin%2f
/admin%252f
/%2e/admin
/admin/..;/
/public/.;x/../admin
/admin\..\admin
/admin<NBSP>       (non-breaking space, masih sering lolos di Node/Flask)
```

Kasus 2026: CVE-2026-124680, Apache APISIX 0.9-3.19.0, auth route bypass lewat
mismatch normalisasi routing versus upstream forwarding, fix di 3.20.0.
Varian hidup lain: matrix parameter `;` (cloudflared 3106f94), Nginx Lua RBAC
yang cocokkan `ngx.var.request_uri` mentah (Malcolm 1055), OData `$batch
multipart/mixed` yang tembus WAF, line folding `\r\n\t` (riset Rafa).

## Workflow 6 langkah

1. Scope dulu, terutama program yang cuma bayar impact finansial.
2. Baseline `curl -i`, catat Server, panjang body, cookie.
3. Tentukan layer yang memblokir (front-end atau aplikasi).
4. Uji satu variabel per request: header, lalu method, lalu encoding path.
5. Bandingkan status, content-length, hash body. 403 vs 401/302/200 adalah sinyal.
6. Bukti impact: baca data admin atau ubah state dalam scope. 200 tanpa data
   bukan temuan kuat.

Alat: curl, ffuf, nomore403, Burp 403 Bypasser, Autorize.

## Jangan dilaporkan

- 403 jadi 200 tapi isinya login/empty shell.
- PUT/DELETE tersedia di REST API tanpa pembeda auth.
- `%00` atau `%c0%af` yang tidak mengubah hasil.
- TRACE aktif tanpa impact token/XSS yang bisa dibuktikan.
