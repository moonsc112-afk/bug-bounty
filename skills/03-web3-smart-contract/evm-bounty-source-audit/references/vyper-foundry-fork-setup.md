# Foundry with Vyper sources and pinned-block fork PoCs

Use when the target repo mixes Vyper and Solidity, or when its test suite forks mainnet at a fixed block.

- **Install the Vyper compiler before building.** Foundry refuses `.vy` sources with "no compiler versions are available" until a `vyper` executable is on PATH. `uv tool install vyper` followed by `export PATH="$HOME/.local/bin:$HOME/.foundry/bin:$PATH"` in the same shell as `forge build` resolves this. Keep the PATH export in the build call, not only in an earlier shell.
- **Initialize top-level submodules first.** A shallow clone has empty `lib/` directories; `git submodule update --init --force --depth 1` is enough to build. Recursive init can chase long dependency chains and time out without changing the build outcome.
- **Probe archive state at the exact pinned block.** Send one `eth_getBalance` at that block to each candidate RPC before running fork tests. An endpoint that serves current state may reject historical state, so a green current-block probe is not sufficient.
- **Run single-contract PoCs before full suites.** Tests that call `vm.createFork` per test multiply RPC requests and can exhaust a public endpoint's rate limit. A failure list dominated by HTTP 429 or historical-state errors is a transport result, not a protocol result; tee output to a log and re-run the isolated contract. For multi-suite sweeps on a shared archive endpoint, also set `FOUNDRY_FUZZ_RUNS=4` to cut per-test RPC traffic.
- **Copy built artifacts into nested dependency submodules instead of rebuilding them.** When a consumer repo's tests call `deployCode("lib/<dep>/out/<Contract>/<Contract>.json")`, copy the dependency's already-built `out/` into that nested path. Rebuilding the nested checkout often fails on empty transitive Vyper lib directories, and the artifact copy matches what the consumer tests expect.
- **Give each fork fixture trove a unique `owner_index` and pre-fund idle liquidity.** Opening several troves in one block with the same `owner_index` reuses the same trove id, and thin Lender idle makes later opens redeem earlier troves into zombie status; both show up as confusing `!active` reverts far from the real fixture mistake.
- **Keep PoCs self-contained in the audited repo.** Add one test file under the repo's `test/` tree and leave protocol source untouched, so the reproducer can be re-run by a reviewer with the same commands.
