# Decision-bound escrow boards, proposal bonds, staked workers

For brain/governance-run systems where a trusted recorder writes decisions on chain and contracts turn them into money moves (task escrow boards with windows, proposal bonds, staked workers, reward rounds). Bug classes below are code-verified on a live deployment; each entry carries the reproduction pattern.

## Verified bug classes

- **Latest-of binding vs a windowed-path guard = supersession dodge.** When one action binds to `latestOf(subject, kind) == decisionId` but another path's guard only tests "a decision was recorded inside [createdAt, deadline]" (bond burn vs refund/expire), a NEWER decision recorded OUTSIDE the window flips both at once: the in-window decision becomes un-settleable (StaleDecision) while the windowed path's guard passes → the punishable state is dodged. Live case: ProposalBonds — K1 "keep" in-window should burn the proposer's bond; once K2 (same subject) is recorded after the deadline, `settle(K1)` reverts StaleDecision, `settle(K2)` reverts BadDecision (recordedAt > deadline), and `expire()` passes its latest-only in-window check and refunds the bond — contradicting the contract's own natspec. Test it explicitly: K1 in-window, K2 post-window, then walk EVERY settle/expire path. The repo's own invariant mirror is often written from the same latest-only rule, so it cannot catch this — check what the test asserts before trusting a green suite. Deliverable: minimal Foundry repro + a control arm (single-decision case still burns). Fix direction for the report: let settle() apply any unused in-window decision for the subject (not only the latest), and make the windowed path refuse while an in-window decision was never settled.
- **Per-subject counters with N authorized callers are unscoped.** A hold/release counter keyed by account only, where every authorized contract (slasher/board/keeper) may decrement it: any authorized caller frees another's hold → the locked resource escapes (worker withdraws its whole stake mid-task, the later slash burns 0), voiding the "there is always stake left to slash" invariant. Fix shape: namespace by caller (`held[caller][account]`). Grade reachability from the LIVE authorized set (sweep `slashers(address)` / equivalent over every candidate): a single live caller = hardening tier (needs an admin add), two or more = live path.
- **Admin list mutations vs in-flight state.** Removing a contract from an authorized list (slasher/keeper) while it still holds state makes its settlement calls revert → that state strands until re-listed. Read every admin mutator against outstanding per-contract state; "retired entries stay listed until their last item settles" policies are the intended guard — verify they hold, then file the gap as an ops note, not a finding.
- **Conservation check — do it live (or on a fork) for every escrow/bookkeeping contract.** Re-derive the contract's own accounting from chain state and compare against balances: escrow → Σ unsettled bounties + open bonds == `token.balanceOf(contract)` exactly; books → Σ per-book amounts == balance and Σ per-(book, token) holdings == `balanceOf(token)`. Batch the per-id getters in chunks of ~10 `eth_call`s, parse per-id (a batch can return 200 with ids missing). Zero diff = soundness evidence worth stating in the operator report; a non-zero diff is a fund-loss lead. Run it before deep reads too — it sizes real exposure and catches live mis-configuration for minutes of work. It also bounds findings: "board holds X, escrow diff 0, all windows bounded" is what a reviewer checks first.
- **History arm of the same check: reconcile the FULL event log, not only current state.** Fetch every log of each fund-holding contract from its deployment block (address-only `eth_getLogs`), decode by topic0 (`cast keccak "<Event(type,...)>"`) and reconcile: Sum(posted) == Sum(paid) + Sum(refunded) + open balance (exact wei); fee events == fee bps on every paid item; every item settles exactly once (no id with two terminal events); cumulative systems (rounds/claims) Sum(claimed) == Sum(allocated). This catches what a current-state check cannot (a historical drift, a mis-settled item now invisible) and produces the report's clean numbers. Two pitfalls: (1) public RPCs cap `eth_getLogs` span (observed 10,000,000 blocks) with an inclusive check — request `[start, start+cap-1]` or end at `latest`; a "spans cap+1 blocks" rejection is an off-by-one, not a dead endpoint; (2) decode against the source signature's indexed/data split — an amount read from the wrong data word silently sums to 0, so a "0 total" that contradicts state is a decode bug, not a finding. If state and history still disagree, re-fetch the state per item with retries before suspecting the contract.

## Reproduction + write-up pattern

- A second-opinion reviewer that fails on a transient rate limit is NOT a covered lens. Absorb its assigned lens yourself or re-dispatch after the limit clears; record which lenses actually produced a verdict before calling the review complete.
- Reproduce every reviewer/lead candidate as a MINIMAL Foundry test in the revision-matching clone (see `references/evm-live-recon-and-fork-harness.md` § 0), with a CONTROL arm proving the delta (e.g. single-decision case still burns) and `vm.expectRevert(Selector.selector)` on each blocked path. Quote the PASS lines (test name + gas) verbatim in the operator report; ship the .t.sol + a sha256 alongside.
- Before drafting: map each candidate to the program's award-table row. "Hardening / edge case with no path to funds" = credit-only even with a failing-Foundry PoC; findings whose only affected funds belong to the submitting side (a proposer's bond escaping its own burn) do not upgrade by having a repro. State expected tier + odds to the operator and let them decide whether to file.
